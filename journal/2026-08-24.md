# 2026-08-24 개발 일지

## 오늘 한 일

1. **첫 프로토타입 제작** — 투명 배경 이미지(PNG/JPG) 또는 SVG를 넣으면 세이프티/칼선/블리딩 3단계 오프셋 라인을 자동 생성하는 Python 데스크톱 앱(Tkinter) 초안을 만들었다. 핵심 로직은 OpenCV(컨투어 추출) + Shapely(오프셋 계산).
2. **실무 피드백 반영** — 4년차 문구 작가(스티커/씰스티커 칼선 작업) 관점에서 피드백을 받았다:
   - 실제 인쇄용 파일은 전부 CMYK 색공간이며, 웹용 RGB 색상은 인쇄소 제출용으로 부적합하다.
   - 진짜 시간을 잡아먹는 작업은 "도안 외곽선을 따라 칼선을 그리는 것" 그 자체 — 즉 오프셋 트레이싱 알고리즘 방향 자체는 맞다.
   - "찢김"과 "밀림"을 막는 게 핵심 — 오프셋 거리보다 얇은 디테일(가는 촉수, 좁은 목 부분)이 뭉개지거나 잘못 합쳐지면 실제 커팅 시 문제가 생긴다.
3. **찢김/디테일 손실 위험 자동 감지 기능 추가** — 모폴로지 opening 기법(지정 반지름의 원이 통과하지 못하는 부분을 정확히 찾아내는 방식)으로, 도안에서 오프셋 폭보다 얇은 구간을 자동으로 찾아 경고 표시하는 기능을 검증했다. 합성 테스트 이미지(얇은 촉수 + 좁은 목)로 실제 위험 구간만 정확히 잡아내는 것을 확인.
4. **실제 인쇄 납품용 파일 구조 분석** — 실제 인쇄소 제출용 파일(.ai, PDF 호환)을 열어 확인한 결과:
   - 문서 색공간은 확인대로 진짜 CMYK(ICCBased, N=4).
   - 칼선은 CMYK 기준 Magenta 100%(C0 M100 Y0 K0), 스트로크 두께 약 1pt.
   - 트림/가이드 라인은 Cyan 100%(C100 M0 Y0 K0).
   - PDF 레이어(OCG) 구조가 실제 일러스트레이터 레이어 이름과 그대로 매칭됨 — SVG보다 PDF/AI 포맷으로 내보내는 게 실무에 훨씬 정확하다는 것을 확인.
   - 실제 손그림 칼선과 자동 트레이스 결과를 같은 도안 위에 겹쳐 비교 — 전반적인 트레이싱 방향은 유효하지만, 배경이 이미 합쳐진(알파 채널 없는) 완성본 파일에서는 "캐릭터만 분리"가 쉽지 않다는 한계를 확인했다. 이건 원본 소스(레이어 분리된 투명 배경 캐릭터 에셋)를 입력으로 받는 게 정답이라는 결론.
5. **깃허브 사전 조사** — 유사한 오픈소스/상업 도구 존재 확인 (자세한 내용은 README의 "비슷한 프로젝트" 참고). 핵심 오프셋 알고리즘 자체는 이미 존재하지만, CMYK 정밀 매칭과 찢김/밀림 위험 감지를 갖춘 도구는 확인되지 않음 — 여기가 차별점.

## 참고 — 비슷한 프로젝트/서비스 (사전 조사)

- [jsorscher1/sticker-cutline-generator](https://github.com/jsorscher1/sticker-cutline-generator) — MIT 라이선스, 브라우저 기반(OpenCV.js + Clipper.js), 오프셋 슬라이더 + 배치 처리 + SVG 내보내기. 핵심 원리는 동일하지만 CMYK/위험 감지 기능은 없음.
- [stickerit.co 칼선 생성기](https://www.stickerit.co/tools/cutline-generator), [cutcontour.com](https://cutcontour.com/) — 상업 서비스(크레딧제/유료), 비공개 소스.
- [mathandy/svgpathtools](https://github.com/mathandy/svgpathtools) — SVG 패스 처리용 파이썬 라이브러리.
- [mgmax/inkscape-roland-cutstudio](https://github.com/mgmax/inkscape-roland-cutstudio) — 커팅 플로터 연동 도구 (오프셋 생성과는 다른 영역).
- 국내 인쇄소(퍼블로그, 포토몬 등)의 "자동 칼선" 업로드 기능 — 해당 인쇄소 제출 시에만 쓸 수 있는 폐쇄형 기능.
