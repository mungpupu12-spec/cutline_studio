# 2026-10-02 개발 일지

## 오늘 한 일

멍푸: "표시한 두개 칼선이 어그러지거나 다른 칼선과 붙어 있어 개선 하고 칼선 속도 5초이내로 고정하고
완성도 높이고. 수정 하는 거 너무 어려워, 어도비 패스 기능 같은거로 만들어" (패스 편집 범위: "점 끌기
삭제 하고 어도비 핸들까지"). 이어서 "완성하고 판매용 설치 파일도 새로 만들어줘. 그럼 그 프로그램
라이선스는 어떻게 해?"

1. **흰 종이 테두리 스티커 칼선(표시한 두 곳)** -- 격자F(단색 배경 위 흰 테두리 스티커), "아니오 → 무테 →
   자동으로 여러 개 인식"
   - 원인 1(어그러짐): 타원 스티커 아래 캐릭터 두 다리 사이 흰 틈이 테두리와 같은 색이라, 칼선이 그 틈으로
     파고들었다.
   - 원인 2(붙음): 타원 스티커와 바로 아래 원형 스티커의 흰 테두리가 살짝 겹쳐 실루엣 하나로 잡혔고,
     안쪽으로 줄인 칼선이 0.5~0.7mm 목으로 이어졌다. 저장 전 정리가 목을 끊어도 끊긴 자리가 움푹 패고
     두 칼선이 2.0mm 딱 붙어 보였다. 또 아래쪽 절반이 흰 이불인 타원은 흰 그림이 테두리와 이어져 "띠"
     판정이 꺼지면서 칼선이 스티커 외곽(기본 여백 1.2mm)에 붙었다.
   - 원본 손 칼선 72개 실측: 그림(흰색이 아닌 곳)에서 약 1mm 바깥, 스티커 외곽에서는 고른 깊이.
   - 고침(core/image_style.py):
     - `_white_ring_measure`/`_white_ring_cut`: 가장자리 0.3~0.8mm 안쪽이 흰 종이색, 바깥 배경이 그와
       뚜렷이 다르고(색 차 30 이상), 가장자리에서 그림까지 거리가 고른(가운데 절반이 중앙값 0.5~1.6배)
       스티커만 "흰 테두리 스티커". 칼선 = 외곽에서 (테두리 두께 - 1mm) 고르게 안쪽 ∪ 그림에서 1mm
       바깥, 실루엣 0.25mm 안쪽으로 자름. 맞닿은 스티커 사이 가는 뿔은 0.75mm 열기로 없애고, 1.2mm
       미만 목은 끊는다. 떨어진 조각은 조각마다 따로 판단.
     - 흰 테두리 스티커는 "맞닿은 단색 그림 나누기"를 하지 않음(남색 밤하늘과 흰 이불을 둘로 나눠
       칼선이 이불 위를 가로질렀음).
     - 실루엣: 배경 채우기 덩어리가 흰 테두리 스티커면 그 덩어리를 그대로 씀(GrabCut이 두 스티커 사이
       배경 틈까지 메우기도 함). 옆 요소(따로 인식된 스티커)를 끌어오면 쓰지 않음 -- 연회색 바탕 위
       흰 쪽지 그림이 옆 캐릭터 칼선에 합쳐지던 것을 확인하고 막음.
   - 결과(실제 손 칼선 대조, 매칭/IoU/경계차): 격자F 70/72, 0.90, 0.79mm → **72/72, 0.95, 0.32mm**,
     교차·이중·2mm 미만 0곳. 표시한 두 곳: 다리 사이로 파고들지 않고 타원을 따라감, 타원과 원형 칼선이
     떨어져 각자 매끄럽게 돎.
   - 나머지 격자·키스컷 7개 파일은 결과가 전과 완전히 같음(매칭·IoU·경계차·점검 모두 동일).
     ①②③ 흐름 5개 파일도 같음(흰 테두리 변형본 1개만 66→64개, 아래 한계 참고).

2. **속도("아니오 → 무테 → 자동 인식", 멍푸 PC 8코어, 격자F)**: 예전 35.5초.
   - 흰 테두리 스티커는 배경 채우기 덩어리로 바로 칼선을 만들어 가장 느린 GrabCut(요소당 약 0.4초)을
     건너뜀(결과 동일 확인). 테두리 두께 재기는 numpy로(파이썬 반복 → 배열).
   - 파일을 불러온 직후 돌던 "호버용 도안 박스" 계산(큰 시트 15~30초)이 같은 프로그램 안 스레드라
     그동안 누른 칼선 생성이 몇 배 느려졌다 → 별도 작업 프로세스(procpool.submit_background)로.
   - 칸 안 요소 나누기는 불러온 직후 뒤에서 미리(`_auto_boxes_for`, 결과 기억).
   - "아니오(도무송 없음)"를 누르면 요소 칼선을 작업 프로세스들이 뒤에서 미리 계산하고 결과를 기억
     (`_maybe_prefetch_auto`, element_jobs.run_task 기억). 누를 때 설정이 같으면 기억한 결과를 씀.
   - 작업 배정: 박스 위치 대신 큰 작업부터 덜 바쁜 프로세스로 고르게(미리 계산과 실제 계산이 같은
     배정 -- `procpool._assign`).
   - 미리보기 PNG 파일 저장은 뒤에서(화면은 메모리 그림을 씀).
   - 칼선 다각형 점 줄이기(원래 선에서 0.02mm 이내, 스티커당 약 1,300 → 100여 개): 겹침 정리·간격
     맞추기·미리보기·저장이 점 수만큼 느렸음. 결과 동일 확인(키스컷 롤 2개는 넓이 0인 찌꺼기 칼선 5개·
     2mm 미만 5곳이 오히려 없어짐).
   - 작업 배정은 같은 칸 요소끼리 한 프로세스로(프로세스마다 자기 칸만 배경 채우기). 무테 보조 탐지의
     요소 찾기는 불러올 때 부가 계산용 프로세스에서 미리(프로그램 켤 때 그 프로세스도 미리 띄움).
   - **멍푸 PC 실측(8코어, 격자F·흰 테두리 변형본, 프로그램을 새로 켜서 한 번씩)**: 파일 불러오고
     "아니오, 없음" 누른 뒤 5초 후 "자동으로 여러 개 인식" → 0.7s / 1.1s, 3초 후 → 2.1s / 6.7s(이때만
     불러오기 자체가 8.5초로 PC가 느렸음), 2초 후(4번) → 2.8s, 2.9s, 3.3s, 2.3s. 예전 35.5s.
     실제 프로그램 화면에서도 눌러서 3초 안에 "칼선 72개" 확인.

3. **칼선 수정(어도비 패스처럼)** -- 새 파일 core/bezier_path.py, gui/path_editor.py
   - 칼선(수백~수천 점 다각형)을 기준점 + 방향 핸들로 된 닫힌 베지어 패스로 바꿈(Schneider 곡선 맞춤,
     벗어남 0.1mm 이내, 원형 스티커 기준점 4~15개, 꺾이는 곳은 뾰족한 점).
   - 미리보기 위 "🖊 칼선 수정": 칼선 클릭 → 기준점 표시, 점 끌기, 핸들 끌기(부드러운 점은 반대쪽
     일직선 유지, Alt = 한쪽만), 선 위 더블클릭 = 점 추가(모양 그대로), 점 더블클릭 = 뾰족/둥근 점,
     Delete = 점 삭제(점을 안 고르면 칼선 삭제), 선 잡고 끌기 = 칼선 이동, 방향키 0.1mm(Shift 1mm),
     Ctrl+Z 되돌리기(60번), Esc 해제/끝. "같은 그림 모두 적용"(기본 켬): 모양이 같은 반복 칸 칼선에도
     똑같이(칸 크기 차이는 비율로).
   - 고친 칼선은 바로 저장 대상에 들어가고 저장 전 점검도 그대로 거침.
   - 멍푸 PC 실제 화면에서 확인: 칼선 클릭 → 파란 패스·기준점, 점 끌기(같은 그림 타원 칼선도 같이
     바뀜), Ctrl+Z 되돌리기(둘 다 원래대로), 선 더블클릭 점 추가, 끝내면 미리보기에 반영. 도구 줄이
     좁은 창에서 잘려 버튼 줄과 설명 줄로 나눔.
   - SVG 내보내기: 칼선을 곡선(C) 패스로 씀 -- 일러스트레이터에서 열면 기준점 십여 개짜리 패스(예전엔
     꺾은선 점 수백~수천 개). 프로그램에서 고친 칼선은 고친 패스 그대로.
