# 2026-10-11 개발 일지

## 오늘 한 일

멍푸(키스컷 롤 화면 캡처, 작업 종류 "무테"): "칼선 종류에 키스컷 포함해서 칼선이 왜 제대로 인식 안 되는지 파악해"

1. **원인 1 -- 그림이 아닌 레이어까지 그림으로 읽음**: 키스컷 롤 .ai(좋은 예 옛 버전, 나쁜 예)는 롤 조각마다 다른
   그림 3장이 들어 있어, 프로그램이 페이지를 통째로 그려 작업 이미지로 썼다. 이때 이미 그려 둔 칼선(마젠타),
   화이트, 참고 레이어(롤 전체를 가로지르는 빨강·초록·파랑 선), "제출시 삭제" 레이어까지 함께 그려져 자동 인식이
   이 선들을 그림으로 봤다. -> 페이지를 그릴 때 이름으로 알아본 칼선·화이트·참고·가이드·삭제·재단 레이어는 끄고
   그림 레이어만 그린다(core.ai_import._hide_non_art_layers). 그림 레이어가 하나도 안 남으면 그대로. 그림이 한 장인
   격자 시트 9개 파일은 원래 이미지를 그대로 꺼내 쓰므로 영향 없음(작업 이미지 크기 그대로 확인).
2. **원인 2 -- 키스컷을 요소마다 따로 따던 방식의 한계**: "자동으로 여러 개 인식"이 롤을 요소 상자로 나눠 실루엣을
   하나씩 땄다. 실제 결과(좋은 예 칼선 대조): 흩어진 반짝이·작은 별 묶음은 사각형 칼선, 하트·타원은 칼선이 그림
   안을 가로지름, 좋은 예처럼 가까운 조각을 한 칼선으로 묶지 못함 -- 67개 중 40개 일치(겹침 0.81, 경계 차이
   1.5mm), 롤 하나에 33초. 그림만 남긴 이미지에서도 34개.
   -> 키스컷 + 투명 배경 그림이면 좋은 예 방식(그림 모양에서 1.3mm 고르게 띄우고 2mm보다 가까운 조각은 합침)으로
   만든다(gui.white_layer_ui._wl_kisscut_auto). 실제 프로그램 흐름 결과: 60개 모두 일치(겹침 0.984, 경계 차이
   0.07mm), 1.8초. 꽉 찬(투명하지 않은) 그림은 예전 방식 그대로.
3. **무테·유테로 고르면**: 무테는 그림 가장자리 안쪽을 자르는 방식(테두리 없는 스티커용), 유테는 조각마다 따로
   따라가는 방식이라 키스컷 롤의 칼선(그림 밖 1.3mm, 가까운 조각 묶음)과 원래 다르다. 좋은 예 대조: 무테 16~31개,
   유테 31~33개 일치. 롤은 "키스컷"으로 골라야 한다.
4. 나쁜 예 파일에 새 키스컷을 돌리면 나쁜 예 칼선과는 59/60개가 겹치지만 경계 차이 0.45mm -- 나쁜 예 칼선은
   더 느슨하고 둥글게 뭉개져 있고, 새 결과는 좋은 예처럼 고르게 1.3mm.
5. 시험 2개 추가(그림 아닌 레이어 끄기 -- 레이어 이름 규칙 확인용으로 PDF를 직접 만듦, 키스컷 자동). 전체
   132 통과 / 기존 실패 1개 그대로.

## 화이트·도움말·문구 정리 (같은 날 이어서)

1. 화이트 레이어 카드: "화이트 없음" 글자를 체크박스 "화이트 넣기"로 바꿈(체크를 풀면 저장에서 빠짐). 보기 버튼
   "적용된 모습 / 화이트만". 화면에서는 화이트를 파란색으로 보여 주고 저장은 흰색. 버튼 이름 "화이트 크기 조정",
   "칼선 재설정".
2. 머리줄 "화면 초기화" 옆에 "도움말" 버튼 -- 기능마다 한 줄 설명과 사용법을 담은 창(gui/help_guide.py).
   무테 = 선화 없이 그린 그림, 유테 = 선화가 있는 그림이라는 설명을 넣음.
3. 화면 문구 정리(빨간 표시): 설명 줄은 모두 "~합니다/~입니다." 문장으로 통일하고 군더더기를 뺌.
   예: "예, 있음 / 아니오, 없음" -> "있음 / 없음", "이 영역 추가 + 미리보기" -> "선택 영역 추가",
   "누적 초기화 (모두 지우기)" -> "누적 초기화", "칼선 내보내기 (PNG)" -> "칼선 내보내기"(PNG·SVG 둘 다 저장되므로),
   작업 종류 "키스컷" -> "키스컷 (마스킹테이프)", 유테/무테 간격 칸 이름 "간격" -> "칼선 간격".
4. 도움말 보강(노란 표시): 오프셋 간격과 도무송 세부 옵션을 실제 코드 동작대로 자세히 적음.
   - 조각: 세 선 모두 그림 바깥쪽 거리. 가장 안쪽 선이 2mm보다 가까우면 세 선을 같이 밀어 2mm를 맞춘다
     (OffsetSpec.enforce_minimum_gap) -- 그래서 기본값 1/2/3mm는 실제로 2/3/4mm 자리에 그려진다.
   - 도무송: 칼선과 블리딩 모두 그림 안쪽. 블리딩 값(최소 2mm)만큼 안쪽에 칼선, 세이프티 선은 그리지 않음.
   - 확인 중 발견: 도무송 세부 옵션의 "배경 자동 분리(GrabCut)" 체크박스 값은 지금 어디서도 읽지 않는다
     (2026-09-28 도무송을 그림 안쪽 기준으로 바꾼 뒤부터). 도움말에는 결과가 같다고 사실대로 적고, 뺄지 멍푸에게 물음.
5. 마우스를 2초 올려 두면 10자 이내 설명이 뜸(gui/tooltips.py). 앱 전체에 Enter/Leave를 한 번 걸고, 마우스가 올라간
   위젯에서 부모 쪽으로 올라가며 등록된 설명을 찾는다(CTk 버튼 안쪽 캔버스·라벨로 옮겨 가도 사라지지 않게).
   Xvfb에서 실제 마우스를 옮겨 확인: 1.5초엔 안 뜨고 2.0초에 뜸, 벗어나면 사라짐.
6. 시험 2개 추가(모든 버튼·체크박스·입력 칸에 설명이 있는지와 10자 이내인지, 옛 문구가 남지 않았는지와 도움말
   문장 끝). 전체 137 통과 / 기존 실패 1개 그대로.
